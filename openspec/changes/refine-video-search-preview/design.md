## Decisions

### 焦点归属搜索栏

静态证据：截图显示围绕输入文本区的粗黑框；预览 `.query-input` 未定义焦点轮廓，仅设置 `outline-offset:5px`，保留了浏览器的默认 outline。尚未通过运行检查确认计算样式。

移除该输入框的默认矩形轮廓，使用搜索栏 `:focus-within` 的低饱和底边与极淡背景响应，150ms 颜色过渡，不改变尺寸。键盘 `:focus-visible` 使用更清楚的整栏底边，按钮保留独立焦点。相比把黑框换成粉框，这种方式不把视觉焦点局限在文本区域，也避免输入后突然出现一层盒子。相比完全移除焦点，仍为键盘操作提供定位。

### 输入决定内容区

| 状态 | 内容区 | 进入方式 |
| --- | --- | --- |
| 空输入 | 热搜、最近搜索 | 首次打开、清空、仅空白字符 |
| 输入中 | 单列联想，无热搜、历史、额外标题 | 输入或修改非空内容 |
| 已提交 | 四列视频卡片及分页 | 回车、搜索按钮、点击联想/历史/热搜 |

输入中移除原左右两栏及分隔线，让联想自然占满内容区；无需为被隐藏的区域保留空白。重新编辑结果页关键词回到联想态。展示区域由状态分支控制，不仅通过 CSS 遮挡旧内容。

### 历史与结果分离

历史仅存关键词，按最近使用排序，去除首尾空白并去重，保留最多10条；展示时取前10条并限制最多3行。只在真正提交搜索后更新，输入、悬停或上下选择不写历史。

当前预览仅向宿主保存 `{ recent: string[] }`，不保存输入草稿、结果数组、页码、滚动位置和选中视频。关闭再打开仍可复用当前会话内的结果，刷新或重启回到空输入并展示历史；这是为兼顾此前“保留上次操作”与最新“不缓存结果”而采用的实现判断。

未来正式接入：为历史使用独立版本化存储；旧搜索快照至多提取已提交关键词，丢弃结果等快照字段。不把输入草稿当成搜索记录，不清理其他业务存储。具体旧键及账号隔离方式由接入时读取实际代码后确定。

## Risks / Trade-offs

- 焦点强调过淡 → 键盘焦点增加底边对比度，按钮焦点保留；由用户查看预览决定视觉效果。
- 窄宽度长词溢出 → 单词省略、最多3行，超出行的按钮同时移出可见及键盘遍历范围。
- 样例不等于真实联想 → 原型使用固定示例，不调用网络；接入后使用真实服务并处理旧响应覆盖、失败及空结果。
- 当前其他工作可能继续修改播放器 → 本次不接触产品源码；正式接入前重新读取，不覆盖并行成果。

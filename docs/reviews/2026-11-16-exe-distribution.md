# EXE 分发与代码审查（2026-11-16）

> 本文记录先前“仅静态审查”阶段。用户随后明确授权测试、打包和发布，后续升级至 Electron 45.3.3 并执行验证；最新结果以 [1.3.0 发布记录](../releases/1.3.0.md) 为准。下文的未验证状态与 Electron 36.9.5 是审查当时的状态。

## 结论与证据边界

当前链路能把 Electron 运行时与前端一起打包，下载者不需要安装 Node.js，也不需要开发者电脑上的 D 盘目录。每个 Windows 用户使用自己 AppData 下的应用数据并自行登录 B站。按当前打包配置，开发者的 AppData 会话不会被自动收进 EXE。

但不能据此保证“换一台电脑没有 bug”或“没有数据安全问题”。本轮已修改若干可从源码确认的问题，仍有运行时维护、本机隐私、网络兼容和公开分发资源授权问题。建议将尚未完成运行验证的产物标为预发布版本，不将本报告作为安全认证。

范围是审查时的当前工作树，包含原有未提交的搜索、历史与播放器改动。只读源码、配置、依赖声明、文件清单及 diff；未读取真实用户 AppData/Cookie/缓存，未调用 B站业务接口。按用户要求，没有运行测试、lint、类型检查、语法检查、启动验证、构建或打包；现有 EXE 没有更新。

## 本轮发现并修改的源码问题

| 优先级 | 触发条件与原因 | 修改及位置 |
| --- | --- | --- |
| P1 | 切换视频或重新准备播放后，媒体代理仍使用同一个随机前缀和 `v-0`/`a-0` 路径；延迟到达的旧请求可能取得新视频的字节。 | `electron/bilibili/media.cjs` 每次 prepare 生成新 token，reset 立即使旧 token 失效。 |
| P1 | 退出登录依次清理连接、存储、磁盘文件；任一步失败都会跳过后续步骤与账号广播，界面可能继续显示旧账号，临时加密文件也未删除。 | `account.cjs` 先广播账号失效，再等待请求/写入结束，独立尝试所有清理，失败明确报告可能恢复旧登录；Profile 页面提供清除重试。删除目标仅为本应用的会话和临时文件。 |
| P2 | `signed()` 等待 nav 或 `post()` 等待 CSRF Cookie 时发生 reset，原请求可能在 reset 结束后继续。 | `client.cjs` 增加会话代次检查，取消过期的异步续步；主动取消不再一律报告网络故障。 |
| P2 | 媒体服务监听失败会阻断页面加载；`loadFile/loadURL` 的 Promise 未等待，启动错误没有统一处理。 | 抽出 `electron/window.cjs`，`main.cjs` 等待初始化与加载，失败显示明确提示并退出，提前注册清理。 |
| P2 | 本机代理对 URL 的解析发生在异常处理外，畸形请求可能产生未处理的 Promise 拒绝。 | `media.cjs` 对解析失败返回 400，并检查请求 origin、Host 与当前 token。 |
| P2 | 生产页面没有 CSP，主窗口未配置权限处理。 | 在 Vite 生产构建中注入 CSP；脚本限本地，媒体连接限回环，图片限本地/data/blob/B站图片域，禁止子框架和对象。主窗口只允许现有复制功能需要的剪贴板写入，拒绝其他权限。 |
| P2 | 历史缓存将 `loaded: true` 跨重启恢复，打开历史不再重新获取；旧游标可能继续参与分页。 | `history/storage.ts` 保留已有内容和筛选，但恢复时重置 loaded、页码及游标，打开时重新请求；成功后显示服务端第一页并重置滚动，失败时保留缓存。 |
| P2 | 损坏的顶层集合可以覆盖初始状态，部分页面在访问数组时崩溃。 | `state/persistence.ts` 对核心集合、线程基础内容作恢复检查；这是有限的恢复处理，并非全量数据 schema 验证。 |
| P3 | 每 650ms 无条件序列化并写入整个工作区，即使没有变化也持续执行。 | `state/store.tsx` 只持久化变化后的状态；保留关闭/隐藏时的保存逻辑。 |

此外，账号加密保存的异常处理现在涵盖 Cookie 读取与加密本身；`.gitignore` 补充会话临时文件。独立静态复核发现“拒绝所有权限”会破坏复制功能，已按上述最小权限调整。

这些是源码层面的修复，运行效果未验证。生产 CSP 尤其需要在未来获准验证时确认 DASH 初始化、动态导入、二维码、字体和头像覆盖面。

## 数据实际流向与保留

| 数据 | 处理方式 | 边界 |
| --- | --- | --- |
| 密码、短信验证码 | 隔离的 B站官方登录窗口；业务代码只选择登录页签 | 官方页面仍由内置 Electron/Chromium 加载，因此运行时安全更新很重要。 |
| B站 Cookie | 主进程的独立内存 session；通过 safeStorage 加密为 `bilibili-session.bin` | Windows 系统加密不等于抵御同一 Windows 用户下的恶意程序、管理员或已被攻陷的进程。 |
| 视频、字幕、弹幕 | 主进程获取；媒体经 `127.0.0.1` 随机端口代理，字幕/弹幕由无账号凭据的 session 下载 | 视频转发不携带账号 Cookie；本机媒体 URL 是临时访问凭证，不应分享。任意本机进程读取能力不在隔离保证内。 |
| 观看历史与搜索词 | renderer 的 localStorage，按 B站 UID 分键 | **明文落盘，退出登录后保留**。UID 分键用于避免界面串号，不是加密或 OS 权限边界。 |
| 聊天、布局、演示工作区、设置 | 应用级 localStorage | **明文落盘，且不按 B站账号隔离**。同一 Windows 用户打开该应用可看到之前聊天。不要在模拟聊天/设置中输入真实密码、API Key 或机密材料。 |
| 播放进度 | `historyHeartbeat` 向 B站上报 | 实际观看会改变 B站账号的服务端历史，不只是本机标记。 |

开发版数据目录为 `%APPDATA%\CodexBilibiliPlayer-Dev`，打包版为 `%APPDATA%\CodexBilibiliPlayer`。目前的“便携 EXE”只是免安装程序，删除 EXE 不会删除这些数据。

按原有历史功能设计，本轮没有改掉“退出后保留记录”的约定，也没有删除任何现存用户缓存。如产品需要适合共用电脑，应单独提供明确的“清除本机个人数据”功能，并决定聊天是否按账号隔离；不能把目前的退出登录描述为彻底清除隐私。

## 仍影响 GitHub 分发的事项

1. **P1：运行时安全维护。** `package.json` 与本地 runtime/version 均为 Electron 36.9.5，打包使用 `.runtime/electron`。本轮没有核对实时安全公告，不能声称此版本没有已知漏洞。发布前需要选用仍获维护的 Electron，并同步实际打包运行时；只改 npm 声明而不更新这个目录无效。本轮未进行未经验证的大版本升级。
2. **P2：CDN 故障恢复有限。** `media-url.cjs` 会从服务端提供的地址中选一个支持的地址，但请求失败时不会逐个切换到其他备用 CDN；前端 DASH 重试次数也设置为 0。其他用户的网络若无法访问所选 CDN，会遇到播放失败。现有重试入口可以重新取流，但不保证换到可用节点。
3. **P2：真实接口尚有外部依赖。** 搜索、历史、字幕、弹幕使用主站社区接口，签名、风控、手机号状态字段或返回格式变化都可能使功能失效。会员/付费/地区限制仍然生效。官方登录页 DOM 变化也可能让自动选择密码/短信页签失效。源码不能证明每个账号都能成功。
4. **P2：平台与分发身份。** 当前只产出 Windows x64 portable，未配置代码签名。Windows SmartScreen/杀毒软件可能警告或阻止运行；企业策略、回环网络限制、临时目录权限也可能阻断启动。ARM64、旧版 Windows、不同 GPU/DPI 的适配没有在本轮确认。
5. **P2：版本识别。** 版本号仍为 1.2.2，而仓库文档明确旧 1.2.2 EXE 不含近期 B站功能。下一次实际发布应使用新的版本号、对应源码提交和明确的发布说明，避免用户拿旧包反馈新功能问题。未发现自动更新链路，后续修复依赖重新下载。
6. **公开分发资源授权。** `docs/sources.md` 明确应用图标和 `public/blossom.svg` 来自原版应用，原用途是本地界面研究；项目未确定自有代码许可证。这不是可通过代码重构消除的问题。公开分发前应替换未明确可再分发的品牌/图标素材或取得相应授权，并整理第三方许可。不能从源仓库公开可见推导出桌面资源可随意再分发。

## 模块边界

- `electron/main.cjs`：应用路径、单实例与生命周期、启动错误。
- `electron/window.cjs`：主窗口、安全配置、窗口 IPC。
- `electron/bilibili/account.cjs` / `client.cjs`：官方登录、凭据持久化、请求与取消。
- `electron/bilibili/media-url.cjs` / `media.cjs`：CDN 地址策略与本机流媒体代理。
- 原有 `search.cjs`、`history.cjs`、`captions.cjs`：各自业务数据；`index.cjs` 负责组合与 IPC 分发。
- `src/state/persistence.ts`：界面状态恢复与保存；`store.tsx`：React 状态与保存调度。
- 原有 `features/account`、`video`、`video-search`、`history`：前端功能边界；仍共用一个视频播放会话。

现有模块划分总体可继续维护，本轮没有充分理由重写整个播放器或拆成多个进程/服务。

## 发布产物边界

`build.files` 包含 `dist/**/*`、`electron/**/*`、`package.json`；electron-builder 还会处理运行时与生产依赖。`appData`、开发日志、源码历史、仓库目录不在这组应用文件路径中。源码中的 `D:/workspace/...` 是模拟场景文本，不是启动必需的本机路径。

上述结论依据配置和所查文件，未检查新生成的 ASAR/EXE，因为本轮没有打包。未来应只上传目标发布产物和必要许可，不把 AppData、会话文件、调试目录或整个开发工作目录作为附件上传。二进制文件亦可被提取，不应把任何共享服务密钥硬编码进前端或 Electron 主进程。
